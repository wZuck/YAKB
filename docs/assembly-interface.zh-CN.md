# 外壳方向与 USB 连接状态

[English](assembly-interface.md)

## HHKB 上框方向修复

底行从左侧1.5u处开始，到12.5u处结束。因此15u宽度内，左挡块为1.5u、右挡块为2.5u，空格为中心轴6u。

此前渲染脚本对Y轴做镜像，而交付STEP/STL使用了另一套方向；把原始模型调整为“从键盘正面看、空格朝下”时，会出现左右挡块与渲染不符。这是文件坐标不一致，不能用透视角度解释。

现在所有交付STEP/STL/DXF统一为右手坐标：**X向右、Y向键盘后方、Z向PCB上方**。从+Z看，+Y为画面上方，空格位于-Y。KiCad屏幕坐标和设计JSON仍以y朝使用者为正；输出时仅做一次`CAD Y=-y`转换，渲染不再镜像。底壳STL为打印另做底面找平旋转。

![实际交付模型正面俯视](../assets/case-top-render.png)

`verify_mechanical_frame.py`检查实际保存的上框非对称挡块实体和PCB/模块包络方向，防止“只修图片、未修模型”。构造坐标下上框左挡块实体宽28.4mm、右47.7mm；与键帽边缘之间保留间隙。

## 当前 Type-C 接口在哪里

当前PCB的nice!nano位于右前侧背面（KiCad构造坐标中心约x=258.73、y=85mm），模块USB朝左。当前外壳USB开口位于左后侧，x约18.65mm，CAD Y约+7mm。**该外壳开口不直接对准模块USB口。**

原设计依赖“外部数据线 → 外壳后侧USB-C母口 → 内部数据延长线 → nice!nano USB-C公头”。但是目前只有外壳开口和模块插头局部包络，没有已选型的整套延长组件、连续线缆走廊与母口固定结构。因此不能据此前的局部无碰撞报告判断闭壳USB可装配。

在接口改版完成前，裸板调试可直接接模块USB；原外壳USB方案应标记为**未完成机械装配验证，不宜据此直接制造成品壳**。若保留模块位置，需要选定可采购数据延长组件并补齐固定和全线束干涉测试；若主控直接靠后侧接口，需要移动主控并重布PCB，再核对NiZ电极、USB插拔空间及天线禁布。

连接关系（表达电气连接，不代表已经确定的线缆路径）：

```mermaid
flowchart LR
    A[外部 USB 数据线] --> B[左后侧 USB-C 母口：待选型与固定]
    B -. 内部数据延长线：待完整建模 .-> C[右前侧 nice!nano USB-C：朝左]
    C --> D[USB HID / 充电]
```
